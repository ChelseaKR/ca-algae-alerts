# i18n status: Applies — English only for 1.0, Spanish is the owner's decision

INTERNATIONALIZATION-STANDARD §1 allows N/A only when all three of its
out-of-scope conditions hold. Two fail here: the site and the app show
natural-language text to the public (condition a) and show dates (condition
c). So the standard applies. Both surfaces are English-only today. Whether
and when to add Spanish is the owner's decision; California's Spanish-speaking
lake users make it a real question for this product.

## Current state

- Site: every page renders `<html lang="en">` from
  `pipeline/src/caalgae/templates/base.html.jinja`. Status sentences live in
  `pipeline/src/caalgae/wording.py`; page strings are inline in the
  templates, with no catalog. Dates are formatted in English
  (`wording.date_label`, "Oct 9, 2026").
- iOS app: `CFBundleDevelopmentRegion` is `en`. Status sentences live in
  `ios/AlgaeCore/Sources/AlgaeCore/StatusWording.swift`, which mirrors
  `wording.py`; view strings are SwiftUI literals, with no
  `Localizable.xcstrings` yet.
- The snapshot carries the state's own water names, spot descriptions and
  advisory levels, verbatim. It carries no UI strings.

## Entry point if this changes

- Site: move `wording.py` and template strings into gettext catalogs and
  render one tree per locale with the right `lang`.
- App: move `StatusWording` and view strings into a String Catalog and add
  `es` to the known regions. The state's advisory levels stay in the
  state's words, with a translated explanation beside them.
